# Qelvra v0.1.0-beta.1

Qelvra's first public beta is a local multi-agent AI workspace for persistent agents, real terminals, tasks and reviewed goals. It is a source-run release licensed under Apache-2.0.

## Capabilities

- Local multi-agent AI workspace.
- Persistent AI agents with saved configuration and filesystem state.
- Real browser terminals backed by PTY sessions.
- Filesystem mailbox messaging between agents.
- Automatic agent-to-agent message routing.
- Persistent task lifecycle: create, assign, execute, review and complete.
- Real-time activity feed.
- Codex and provider discovery layer, with installation/authentication guidance.
- Real AI task execution through the locally installed Codex CLI, with structured results and workspace-file changes.
- Multi-agent Goal → Plan → Run → Review orchestration, including worker assignment, bounded rework and a final summary. Plans require explicit approval before execution.

Provider discovery is broader than automation support: Codex supports real automated work in this beta; other detected CLIs have the support levels described in the provider guide. Deterministic fake agents are a development demonstration and are unavailable in production.

## Getting started

Use Node.js 22 and npm, plus platform build tools if node-pty must compile. Clone the repository and check out `v0.1.0-beta.1`, then follow the [README](https://github.com/aryansharma1305/Qelvra/blob/v0.1.0-beta.1/README.md). The UI runs locally; there is no desktop installer, hosted deployment or npm distribution. Windows has not been release-verified.

Read the [provider guide](https://github.com/aryansharma1305/Qelvra/blob/v0.1.0-beta.1/docs/providers.md), [security guidance](https://github.com/aryansharma1305/Qelvra/blob/v0.1.0-beta.1/SECURITY.md), and [storage/backup instructions](https://github.com/aryansharma1305/Qelvra/blob/v0.1.0-beta.1/docs/architecture.md). Stop the server and back up the entire DATA_DIR before upgrading. Interrupted work requires inspection and explicit retry/resume.

## Current limitations

- Beta / local-first software for one trusted local user.
- Agents currently use isolated workspaces.
- Qelvra does not automatically merge agent code into one project repository.
- Provider availability and authentication depend on locally installed provider CLIs.
- Not intended for untrusted public internet exposure: there is no API authentication. Keep loopback binding; a workspace cwd is not a full OS sandbox.
- Some planned UI capabilities are intentionally disabled in beta: Attachments, Voice, Vector Memory, per-agent Delegation and Lo-Fi playback. Studio/Network/Swarm previews do not imply live telemetry or unsupported controls.

The [beta limitations](https://github.com/aryansharma1305/Qelvra/blob/v0.1.0-beta.1/docs/limitations.md) and SECURITY.md also document platform/support limits and the remaining build-tool dependency advisory. Third-party dependencies and fonts retain their original licenses; redistribution notices are included.

## First beta cycle

Feature work is frozen for this release. The first beta cycle is for bug reports, user testing and fixes only: beta.1 → beta.2 → beta.3 if needed. Do not add Attachments, Voice, Vector Memory, per-agent Delegation, Lo-Fi or shared workspaces during this cycle.

Shared Projects / Git Worktree Collaboration is the intended centerpiece of v0.2: agents work on separate branches/worktrees of one project repository, then submit changes for review and merge. It is future work, not a capability of this beta.
