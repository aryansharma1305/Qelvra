# Providers in v0.1.0-beta.1

Qelvra detects existing CLIs on the server's PATH. Installations, sign-in, models and credentials belong to the provider; Qelvra does not install tools, collect API keys or store provider credentials. Restart Qelvra after changing PATH. Retry discovery after setup; availability is cached for at most a minute. The UI never displays executable paths.

A provider being installed does not prove it is authenticated or ready for automation. Only Codex and the development fake provider support structured automated results in this beta. CLI launch commands and argument structure are server-owned. Task/goal text goes through provider input, never shell interpolation.

## Failures and recovery

- **Not installed:** follow the provider's own instructions; ensure the server sees its PATH, then restart/retry.
- **Sign-in required:** sign in with the provider CLI, then Retry providers. Authentication detection is best-effort; providers with unchecked auth may report launch/execution failure instead.
- **Model not configured:** Ollama model selection is not implemented in Qelvra yet. Choose a supported automation provider for tasks/goals.
- **Detection failed / incompatible CLI:** inspect the server's controlled diagnostic code and provider CLI version/help. Do not supply an executable or custom arguments in the browser.
- **Launch failed:** check installation, permissions and provider availability. A failed start does not count as a running agent.
- **Execution timed out / invalid result:** inspect the task error and workspace edits before retrying. Qelvra cancels its owned process, preserves edits and does not mark an invalid result successful.
- **Storage failure:** repair permissions or restore a stopped-server backup before retrying; do not reset your DATA_DIR.

Retries on provider discovery keep your form draft. Task retry is explicit and may repeat workspace edits; review already-written files first. Provider output, terminal content and mailbox bodies are not copied into Activity. External provider privacy/retention depends on that provider.
